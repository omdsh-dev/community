# P-0001: Lightweight community governance trial

- Status: `discussion`
- Authors: community initiators; open for co-authorship
- Created: 2026-08-15
- Discussion: [Issue #15](https://github.com/omdsh-dev/community/issues/15)
- Implementation draft: [PR #14](https://github.com/omdsh-dev/community/pull/14)
- Affected assets and ratifiers: each repository or organization controller; cross-organization scope remains unconfirmed
- Review or expiry: 30 days after ratified start

## Problem and evidence

The ecosystem is growing across many autonomous repositories, catalogs, markets, tools, and distributions. A single-market governance model would centralize authority and review load. The community instead needs a shared entry point, contribution path, upstream compatibility coordination, public records, and safe routes for sensitive matters.

## Goals and non-goals

Goals: define the community as a collaboration layer; preserve project autonomy and multiple markets; make authority explicit; create lightweight bilingual participation, proposal, decision, compatibility, meeting, and safety infrastructure.

Non-goals: create a permanent committee; designate an official marketplace; transfer repositories or root assets; certify plugin safety; bind `oh-my-dsh`, `omdsh-dev`, independent projects, or upstream without their controllers' confirmation.

## Proposed change

Run a reversible 30-day trial using the documents and structure in PR #14. Trial responsibilities are facilitator, recorder, community maintainer, compatibility coordinator, and security/conduct contact. Routine project work remains project-owned. Cross-project output remains a proposal until the relevant controller ratifies it.

## Alternatives

- Keep only the existing participation README.
- Operate governance inside a single plugin catalog or market.
- Create a permanent steering committee immediately.

The proposal prefers a time-limited collaboration layer because it can be tested and removed without centralizing the ecosystem.

## Impact and safeguards

The trial adds documentation and coordination work, so day-30 review must examine response time, governance-blocked work, compatibility response, volunteer burden, bypass behavior, safety, and due process. Sensitive data stays in private routes. High-impact matters never pass by silence.

## Rollout and rollback

Merge the draft only after public review and controller confirmation for this repository. Announce the trial start and end dates, temporary responsibility holders, private contacts, and review measures. At expiry, continue, simplify, pause, or remove the trial files. Discovery-only and project-local governance remain acceptable outcomes.

## Unresolved questions

- Which controllers ratify the trial for each affected asset?
- Who can safely serve as non-conflicted security and conduct contacts?
- Which three shared services should be prioritized in the first 30 days?
- What measured thresholds should trigger simplification or expiry?
